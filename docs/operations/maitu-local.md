# 脉图本机运行

本页说明 Maitu 的 Windows 本机运行入口。Docker Desktop 使用 Linux 引擎，应用在本机环回端口提供网页，数据库与项目文件放在 Maitu 专用数据卷。

## Windows 启动

在仓库根目录打开 PowerShell，执行：

```powershell
./scripts/start-local.ps1
```

默认地址为 `http://127.0.0.1:3033`，与 Compose 发布的 IPv4 环回端口一致。脚本等待容器就绪，并通过应用健康接口检查数据库可连接。首次启动需要下载基础镜像、安装构建依赖和编译 Rust；后续构建会使用本机缓存。

需要更换端口或启动后打开浏览器时：

```powershell
./scripts/start-local.ps1 -Port 3034 -OpenBrowser
```

## Clash 与代理

脚本优先保留终端已有的代理变量。未设置时读取 Windows 已启用的静态系统代理，为 Docker 构建工具的镜像认证请求设置本次进程代理；结束时恢复原环境。

可以显式指定代理，例如 Clash 的 HTTP 混合端口：

```powershell
./scripts/start-local.ps1 -ProxyUrl http://127.0.0.1:7897
```

Docker Desktop 自身也需要通过其系统代理或手动代理访问镜像仓库。端口以 Clash 实际配置为准。构建容器中的 `127.0.0.1` 指向容器自己，因此脚本在 Docker Desktop 上通过其内部 HTTP 代理处理构建依赖下载。其他环境可以用 `-BuildProxyUrl` 指定容器能访问的代理，或自行设置 `MAITU_BUILD_PROXY`。

代理地址不写入 Git、本机全局配置或运行时应用环境。此启动脚本仅设置当前进程与镜像构建参数。

请求进入 Clash 后仍可能匹配到直连。首次完整测试会下载微软的 Playwright 镜像；如果日志显示 `mcr.microsoft.com` 或其 `data.mcr.microsoft.com` 子域走 `DIRECT` 且下载缓慢，可在 Clash 中把 `mcr.microsoft.com` 的域名后缀规则放在微软直连规则之前，选择可用代理组。此规则包括该镜像站的数据子域，不需要把所有微软请求改成代理。本次验收临时为 Docker 的这些请求设置了代理路径，镜像下载后恢复原规则；启动脚本不修改 Clash 规则。

## 连接 DeepSeek 与使用任务图

打开本机 `/maitu/settings`，填写 DeepSeek 密钥，设置同时执行数并保存。密钥写入独立的 `provider_config` 卷，读取页面不会返回密钥。保存配置不等于请求已验证，通过实际任务结果判断连接是否可用。

连接页显示思考模式、上下文预算与最大输出长度。当前 DeepSeek Flash 和 Pro 的上下文容量为 1,048,576 Token，最大输出为 393,216 Token，参见[官方模型元数据](https://api-docs.deepseek.com/zh-cn/api/list-models/)。按用户选择，新连接默认开启思考，最大输出默认 65,536 Token，与当前思考模式的[官方默认值](https://api-docs.deepseek.com/zh-cn/api/create-chat-completion/)一致；上下文预算默认使用模型容量。输出额度包含思考与最终正文，实际发送为 `max_tokens`。

可以切换为非思考模式，官方参考默认输出为 8,192 Token。切换模式保留用户填写的输出上限，已保存配置缺少模式字段时默认开启思考，已有输出长度与密钥保留。思考开关实际发送到 API，并保存在每次任务的输入记录中；成果文件保存最终正文，用量记录保留服务返回的统计。

连接页保存失败时保留填写内容。配置格式被拒绝时显示整数与思考模式检查提示，异常的非 JSON 回复按 HTTP 状态提示原因。已加载的旧表单提交 `"true"` 或 `"false"` 时，后台会规范化为布尔值；其他不明确的模式值仍拒绝，失败不会修改已有连接。更新网页后会加载本次修正的脚本。

上下文预算是脉图用于安排输入与预留输出的本机设置，不是改变模型容量的 API 参数。输入采用[官方文本比例](https://api-docs.deepseek.com/zh-cn/quick_start/token_usage/)估算，超出预算会在发请求前停止并记录原因；没有自动裁剪资料。估算不能保证准确 Token 数，实际输入和输出用量以返回的 `usage` 为准。完整输入快照另有 8 MiB 的文件大小限制。

连接页不提供超时设置。后台保留连接建立与无数据等待的处理，持续收到数据时允许长输出继续生成；旧配置中的 `timeoutSeconds` 不再决定新请求的总时长。

从首页创建项目，导入 UTF-8 文本文件或粘贴资料，添加独立任务，填写要求与成果文件名。可从节点单独启动，也可以启动全部待执行任务。点击“记录与成果”查看历次尝试、输入、请求时段及失败原因；产出后打开或下载文件，选择“采用这次成果”供后续节点引用。

下载资料任务成果时保留创建任务时填写的文件名，中文与空格通过 UTF-8 文件名响应传递。

关闭网页不会停止后台；刷新后从数据库读取现状。重试保留旧记录，服务中断留下明确的中断状态，需要用户决定是否重发。

## 从目标到编码成果

1. 在项目中选择“导入代码项目”，上传需要处理的文本代码目录，填写一项实际检查的程序和参数，每行一个参数。例如 Node 项目可选择 `node`，参数为 `--test` 和 `tests`。
2. 选择“生成推进图”，写目标并选择资料。DeepSeek 返回建议后，打开规划节点，修改任务要求、成果说明文件名、验收要求与依赖，再采用计划。采用会建立待启动节点，执行仍由你启动。
3. 启动编码节点或全部待执行任务。独立节点在各自工作区运行；需要前序成果的节点等待所需版本被采用。模型实际读取、搜索和修改代码，调用已声明的检查，依据返回结果继续修正。
4. 在“记录与成果”查看真实工具操作、检查退出状态和输出；打开代码差异或成果说明。检查通过的候选可选择“合并检查并采用”，应用合并到当前采用版本并重新检查，冲突和检查失败会保留现场与原因。
5. 从项目代码面板导出采用版本。需要改变要求时，在节点内补充要求并启动新尝试；旧输入、修改和结果继续保留。

导入的是脉图管理的代码副本，操作不回写你选择的原目录。导出采用版本后再用于原项目。每个文本文件最多 1 MiB，项目最多 2,000 个文件、20 MiB；不上传 Git 控制目录、真实环境配置、缓存或凭据目录。完整仓库历史归档另按[旧库迁移方案](legacy-repository-migration.md)执行。

编码任务的“成果说明文件名”用于保存模型的最终说明，例如 `implementation.md`，只能填单个文件名；要修改的 `src/main.rs` 等路径写在任务要求中。代码差异、实际工具操作和检查结果由程序分别保存，不能仅依据模型说明判断执行成功。

当前检查环境包含基础 Node、Python 和 Rust 工具，无网络。项目需要的依赖必须已随导入的文本代码提供，或在固定检查镜像中可用；不能直接运行需要在线下载依赖的完整构建。网页导入表单先配置一项检查，接口可声明多项。编码任务和检查进程分别排队，检查并发当前为 2。

检查服务只在 Compose 内网提供，应用不持有 Docker 接口。实际检查容器只读取本次工作区，没有模型密钥和网络。检查请求编号与回执保存到执行输出卷；同编号不会重复启动进程。连接结果不确定或服务中断时显示中断，保留已经写入的文件和差异，启动新尝试由你决定。

## 管理服务与数据

```powershell
docker compose -f compose.maitu.yaml ps
docker compose -f compose.maitu.yaml logs --tail 100 app
docker compose -f compose.maitu.yaml stop
```

`compose.maitu.yaml` 默认项目名为 `maitu`，使用项目专属的 PostgreSQL、成果、仓库、工作区、执行输出与模型配置卷；旧 `compose.yaml` 是继承来源。可以在启动前设置 `MAITU_INSTANCE` 运行另一套独立实例，并选择空闲端口。继承的备份不导出个人模型密钥，恢复到另一实例时需重新配置。

应用的本机入口关闭账号认证，并只发布 `127.0.0.1` 上的网页端口。迁到远程服务器时采用[安全部署指南](deployment.md)中的独立配置。

当前已完成与尚待验证的行为见[实施进度](../development/maitu-progress.md)。
