# 脉图实施进度

本页记录 Maitu 当前实际完成的工作、验证结果和可接续的下一项任务。计划与已实现行为分开记载。

## 本轮资料任务

2026-10-01，用户接受“读取资料并产出文件”的首轮 Goal，选择 DeepSeek。类别为模型与执行，分支为 `execution/parallel-file-tasks`，在首次修改前已从运行基线分支建立。

任务分支新增实际项目图、UTF-8 资料导入、DeepSeek 配置、可调并发、依赖调度、成果下载与采用、历次尝试和请求时段。配置使用独立本机卷；任务、资料和事件使用 PostgreSQL，文件使用已有成果卷。首页已切换为新工作区，继承页面保留在 `/legacy`。

本机已编译并启动新版。Rust 格式、Clippy 和 62 项单元测试通过。隔离数据库迁移、重复迁移、项目与尝试引用约束通过。独立 HTTP 测试接口验证了三个请求实际重叠、429 失败隔离、手动重试、固定资料与前序版本、并发降为 1、执行器中断恢复，以及超过 128 个依赖等待任务时仍能推进独立任务。

本机真实 Chromium 表单检查通过：文件导入、任务图创建和启动、等待说明、失败与重试记录、输入查看、刷新与移动布局；没有页面脚本错误或服务器 500 响应。检查用关闭的本机端口验证网络失败，不调用付费服务。

本机标准 Docker 构建在 crates.io 下载超时后停止。新版先使用已下载的依赖离线编译，将当前二进制和资源装入原运行镜像后启动；构建增加 Cargo 缓存并关闭代理路径上的 HTTP 多路复用，标准生产镜像和完整质量门正在另外验证。尚未配置个人 DeepSeek 密钥，测试接口结果不能作为真实 DeepSeek 验收，本轮 Goal 尚未完成。

## 运行基线

任务类别为运行与部署，分支为 `infra/docker-first-run`。导入浮点主线的 79 条完整提交，建立 Maitu 产品入口、来源记录和任务分支规则。

Docker Engine 已可连接，Maitu 独立 Compose 配置通过静态校验。Docker 构建工具的终端认证请求初次没有使用系统代理，连接超时；通过 Clash 的已有 HTTP 代理后，开发镜像已构建成功。Windows 启动脚本自动检测系统代理，并将构建依赖下载交给 Docker Desktop 内部代理。

Rust 格式检查、Clippy 和 58 项单元测试通过。生产镜像构建成功，Windows 启动脚本完成服务就绪等待，应用健康接口确认数据库可连接。本机地址为 `http://127.0.0.1:3033`。本机的 `localhost` 在 IPv6 路径上出现超时，启动入口改为 Compose 实际发布的 IPv4 环回地址；支持 `-NoProxy` 的 PowerShell 也会明确绕过代理检查本机服务。

实际浏览器检查通过：从网页创建一个验收项目，桌面页面没有脚本错误，390 像素宽的移动页面没有横向溢出。整套本机容器重新创建后，验收项目仍可读取，数据卷保留了项目记录。启动失败时，Windows 脚本会报错并恢复原代理与端口环境。

任务分支 `dcc163c` 的 [GitHub 完整质量门](https://github.com/Ann5t/maitu/actions/runs/36709377269)已通过，覆盖数据库迁移、HTTP 闭环、浏览器、真实插件、生产镜像、安全部署和备份恢复。本机完整质量门首次运行在 Docker 镜像仓库请求超时时中止，重试在 Python 基础镜像下载阶段停滞，云端检查完成后已终止该次本机重试。本机已完成的构建、Rust 检查、浏览器与数据保留验收单独记为通过。IPv4 入口修正后，启动脚本和实际浏览器复查通过，原验收项目仍可读取。

首次下载微软 Playwright 镜像时，Clash 的微软域名规则仍选择直连；临时为 Docker 对该镜像站的请求选择已有代理组，下载成功后已恢复原规则，未修改 Clash 配置文件。运行基线阶段尚未接通真实模型与工具执行。
