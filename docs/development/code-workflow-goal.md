# 脉图从想法到编码成果 Goal

2026-10-01 更新。状态：目标生成任务图与真实编码已实现，并通过本机真实 DeepSeek、实际检查和重启验收；任务分支交付与完整质量门状态见[实施进度](maitu-progress.md)。这是[整体完成路线](../product/completion-roadmap.md)中的目标推进与编码阶段；已完成的首轮资料任务范围保持为历史验收边界。

## 目标

让用户输入想法，由脉图结合项目资料与代码提出可编辑的任务图，采用计划后从图上启动真实编码任务。模型读取所选代码项目，在独立工作区修改文件并运行检查，根据实际错误继续修正；用户能查看工具操作、代码差异和检查结果，选择采用确定的一次成果。其他独立任务可以继续推进，过程和成果在刷新或服务中断后可追溯。

模型返回代码片段、生成补丁文本或声称检查成功，均不足以完成本 Goal。验收要求代码改动真正落到工作区，检查进程真正运行，采用后的项目代码包含确定的改动。

## 输入与界面

用户选择已有 Git 项目或导入项目副本，明确工作基线和检查方式。初次运行优先选择已有环境支持的小功能；计划使用脉图自身的一个范围明确的改动，不把重建整个脉图交给一个试验节点。

节点显示任务要求、工作区、当前操作、是否需要用户处理、差异与检查结果。代码修改、检查通过和成果采用分别记录。用户可以补充要求后开始新尝试，旧代码成果与旧输入仍可打开。

## 从目标形成可执行任务图

使用已配置 DeepSeek 根据目标、指定资料和项目可用工具生成结构化计划，保存本次输入、模型设置、原始回答和建议版本。每项建议包含目的、具体要求、任务类型、依赖、成果和验收要求；缺少信息时显示问题或明确假设，不声称可以调用尚未接入的工具。

用户能修改任务要求和依赖，再决定加入图中。程序校验重复标识、缺失依赖、环与任务范围，在一次事务中形成真实节点和边；不把无法校验的文本解析为成功计划，也不在用户采用前启动编码。重复采用同一计划不会生成两份相同节点，重新生成保留旧建议。

产生任务图、工具实际执行、验证和采用分别保留状态。资料与编码任务可以在同一项目中连接，后续节点引用明确的前序成果版本。

## 工具与执行

复用并核对 `src/application/workspaces.rs`、`src/runner_protocol.rs`、`src/bin/fudian-runner.rs` 和现有插件工具接口。现有 Runner 能执行既定入口，尚未证明它与 Maitu 的模型工具循环接通；不直接把它标为编码 Agent 已完成。

本轮选择继续用 Rust 持有项目状态与 DeepSeek 工具循环，通过独立内网控制器运行固定的 Docker 检查环境。检查容器只读取单次工作区，没有模型凭据；原 Runner 的固定入口不直接当作已接通的编码 Agent。实现选择和边界见[工作流决定](../decisions/maitu-0002-goal-to-code-workflow.md)。

本轮必要操作为列出与搜索项目文件、读取文本、写入获准工作区、执行项目声明的检查并读取输出。工作区独立于用户原始目录，并固定基线；任务不能自行扩大文件范围或批准自身扩大权限。检查命令按结构化程序与参数执行，结果记录实际退出状态与输出，环境不把模型密钥交给命令进程。

采用写入项目代码前展示明确差异；整合检查在完整候选版本上运行。远端推送、主线合并和部署遵循已授权的范围，不因模型给出指令就发生。检查失败的结果可供用户查看，不能自动显示为验证通过。

## 并行与历史

至少两个独立编码任务基于同一确定基线，在不同工作区产生实际改动。后续整合节点引用确定的成果；如果存在冲突，记录冲突和需要的处理，不静默覆盖其中一个结果。

每次尝试固定要求、输入代码版本、模型配置和工具范围，追加模型请求与工具结果。重试创建新尝试；对工作区、采用结果和检查记录的访问可定位具体版本。应用与模型服务中断时，显示完成、未完成和结果不确定的操作；不自动重放付费请求、采用或远端写入。

网页关闭后，已获得执行资格的后台工作继续。取消或暂停要记录具体达到的状态，不能仅改变显示文字而让进程继续修改文件。

## 验收场景

| 场景 | 必须观察到的结果 |
| --- | --- |
| 目标生成并调整任务图 | 真实 DeepSeek 根据目标与项目资料生成建议；用户调整后采用，生成实际节点与依赖；刷新后可查看原计划和采用结果 |
| 无效计划与重复采用 | 有环或缺失依赖的计划被拒绝且不生成部分节点；重复采用没有重复节点；模型失败保留原因和输入 |
| 单任务完成一个真实改动 | 真实模型请求后，工具读写项目文件并运行检查；产生可打开的差异，检查记录含退出状态，用户采用后代码与成果一致 |
| 检查失败后的修正 | 第一版实际检查失败；模型读取真实错误并作第二次修改；原失败记录保留，最终状态与最后检查结果一致 |
| 两项独立工作并行 | 请求或工具执行时段有重叠；工作区路径不同，文件和检查不会串用；各自输出可单独采用 |
| 有依赖的整合 | 整合使用固定的两项结果，实际检查完整候选；冲突时显示需要处理，没有静默覆盖 |
| 刷新和中断 | 刷新后任务与工具记录一致；执行中终止 Worker 后，重开能定位中断位置，已完成成果保留，外部操作没有被盲目重复 |
| 工具范围拒绝 | 越过工作区或未授权操作被程序拒绝；记录原因，用户源目录不被修改；模型无法自行批准扩大范围 |

隔离测试覆盖故障、重复提交、边界和恢复。它们只证明程序行为；真实 DeepSeek 与真正文件、进程和代码采用另行验收。继续保留用户的当前连接配置和已存在的资料项目。
