# Fudian 前端设计基线

- 日期：2026-08-23
- 范围：只改变服务端 HTML、CSS、少量渐进增强 JavaScript 和前端投影；不改变领域状态机、权限或后端接口语义。
- 当前状态：用户已退回 Session 03，原因是文字过量、信息被拉成清单、缺少视觉层级和使用欲望。

## 1. 设计方向

Fudian 的界面应当像一个安静、精确、可以长期工作的项目控制室，而不是协议文档、管理后台或卡片组件展览。

- **先让人看见正在发生什么。** 每个页面只突出一个当前任务或主入口，协议名、摘要、哈希和实现说明进入按需层。
- **用空间和排版建立关系。** 先靠留白、字号、位置和表面层级分组，边框只用于真实边界，避免每段内容都套卡片。
- **使用用户语言。** 默认界面不出现 projection、runtime、manifest 等实现术语；准确技术信息保留在“详情”中。
- **渐进式披露。** 首屏只显示状态、下一步和关键现场；文件、运行、工具、证据、插件、上下文及审核各有摘要，点击后展开。
- **保持克制的辨识度。** 暖白工作纸、深色导航、酸绿色只用于焦点与进展；不用大面积渐变、装饰性阴影或无意义徽章。

## 2. 布局规则

- 桌面应用外壳由稳定导航、页面标题区和主工作区组成；项目目标工作台内部再分目标图与选中 Session 现场。
- 手机不是缩小的桌面。底部主导航最多五项；目标图和工作现场上下分区，详细记录默认收起。
- 内容页使用有界阅读宽度；工作台使用可用视口宽度。任何主要操作不依赖横向页面滚动。
- 采用 4px 基础间距尺度，常用间距为 8、12、16、24、32、48；同组更近、异组更远。

## 3. 可读性与操作门

- 正文默认 15–16px，重要工作文本不低于 14px，辅助文字不低于 12px。
- 普通正文与背景对比度至少 4.5:1；大号文字至少 3:1。
- 所有主要按钮、导航、折叠标题和移动端交互目标至少 40px 高；任何指针目标不得低于 WCAG 2.2 的 24×24px 最低门槛。
- 键盘焦点必须清楚；减少动画偏好下不保留明显过渡。

## 4. 页面投影

### 想法

- 默认是状态看板：刚记录、发展中、准备立项、已形成项目。
- 时间线与关系图作为次级投影，不改变权威数据。
- 卡片只显示标题、两行内容、来源/关系/提案信号和下一步；版本历史进入详情。

### 项目与目标工作台

- 项目标题与主状态保持紧凑，工作台占据主要视口。
- 目标图负责选择“谁在做什么”；工作现场负责展示选中 Session 的当前任务。
- 工作现场先显示任务、状态、目标、Agent、Git 现场和需要用户处理的动作。
- 文件默认展开；上下文、运行日志、工具、插件、证据、产出和审核根据是否有活动信号决定摘要，默认不把所有正文铺满页面。

### 设置

- 设置是控制面板，不是架构说明。
- 只详细展示已经可操作的设置；尚未接入的 AI 和联网能力只显示一行真实状态。
- 外观选择使用可点击的视觉预览；账号与访问仅展示当前真实模式和可执行动作。

## 5. 本轮验收

- 首页、想法看板、想法详情、目标工作台和设置均有 1440px 与 390px Chromium 现场。
- 想法默认落在看板，四个阶段在桌面直接可见、手机可顺畅浏览。
- 代表性目标工作台的手机页面不再把所有技术记录默认展开；首个视口能识别项目、Session 和当前任务。
- 设置页删除解释性步骤清单，只保留外观、连接状态和访问状态。
- 原有表单、文件导入、契约修订、Evidence、Contribution、拟合并和审核闭环继续通过。
- 视觉候选只能标记“待用户判断”，自动测试不能替用户宣称好看或有使用欲望。
