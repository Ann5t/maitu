# BP-08：Git 图与 Agent 工作现场式多设备工作台目标契约

> 历史归档：本文保留当时的目标、过程或证据，不定义当前产品行为。

## 目标

把现有“枝干车道 + 长详情页”推进为可日常管理的项目工作台：用户从全局看到哪些目标正在推进、等待自己、准备审核或发生冲突；点击任一 Session 后，像走进该 Agent 的工作现场一样，直接看到真实文件/代码输出、浏览器与工具、测试、持久行动、通知、审核和父枝干集成。桌面、平板、手机使用适合各自空间的投影，但不复制或改写领域事实。

## 交互原则

- 一条目标枝干仍是一条目标；Session 是枝干上的工作节点。投影版本可替换，不把坐标、展开状态或筛选结果写成权威领域状态。
- 首屏先回答三件事：现在谁在做什么、哪里需要我、选中现场发生了什么。摘要之后再按需展开契约、环境摘要、哈希、完整上下文和高级操作。
- 图上状态必须来自真实 GoalBranch、Session、Attention、ActionRun、ReviewGate 和 Integration，不能用装饰色伪造“运行”“审核中”或“已集成”。
- 工作现场以权威记录为来源：InputArtifact、RunnerJob/File、ToolCall、ToolLease、ActionEvent、Evidence、Contribution、Notification、ReviewDecision 和 Integration。不存在的数据明确显示为空，不生成假日志。
- 插件先披露名称、版本、能力、安装/撤销状态和工具摘要；用户或 Agent 选中后再展开权限、Runtime 和具体工具。缺失能力形成持久安装请求，不假装已经可用。
- 电脑保持图与现场并列；平板允许可调比例或上下衔接；手机先给可筛选的目标列表，再进入所选 Session 现场。URL 始终可深链到 Session，浏览器前进/后退可恢复选择。
- 所有关键操作可仅用键盘完成，有清晰焦点；触控目标至少 44px。尊重减少动画设置，不以颜色作为唯一状态信号。
- 有意义文字不得小于 `12px`，正文不得小于 `14px`，正文对比度不得低于 4.5:1。此前因小字退回的 Session 01 只作反例，不回归。

## 验收表

- [x] 全局指挥条准确汇总运行中、等待用户、后台行动、未读通知和待审核/集成状态；筛选、搜索与“回到当前现场”不改变领域数据。
- [x] Git 图能表达父子目标、同枝干多 Session、HEAD、暂停、拟合并、审核和物理集成；鼠标、触摸、Tab/方向键/Enter 均可选择并通过 URL 深链恢复。
- [x] Session 工作现场直接展示真实 workspace/Git 身份、输入与 Runner 输出文件、ActionRun/事件、ToolCall、ToolLease/endpoint、测试 Evidence、Contribution、通知、审核与 Integration 进度。
- [x] 插件现场按需披露已安装/撤销版本、签名发布者、能力、工具、权限与 Runtime；可从当前 Session 提交幂等安装请求并在刷新后看到状态，不提供绕过签名安装的网页入口。
- [x] 判断、异常、冲突和集成失败在图、指挥条、现场三处使用一致文字状态；用户能看到安全点、已尝试、风险、建议和下一步。
- [x] 1440px 桌面、820px 平板、390px 手机无页面级横向溢出；核心现场可触达，字号、对比度、44px 触控、键盘焦点、语义标签和减少动画自动检查通过。
- [x] 隔离大图至少包含 100 条目标枝干、300 个 Session、多个 Proposal/暂停/审核/集成与后台行动；服务端首字节和浏览器可交互时间有明确预算，筛选后 DOM/交互不失真。
- [x] 普通规模完整浏览器流程、HTTP 回归、Rust/SQL/Runner/插件/审核集成和发行镜像完整质量门通过；测试不写真实数据且无残留容器/端口。
- [x] 生产容器身份、启动时间、真实数据计数、迁移登记和 Artifact 摘要只读复核不变。
- [ ] 用户在真实桌面或手机上使用候选后接受整体层级、字号、密度、暂停/拟合并表达和想法空间默认投影；机器测试不能替代这一项。

## 性能与披露预算

- 项目页面查询避免按 Session 循环访问数据库；活动、上下文预览与图索引使用有界批量查询。
- 大图初始 HTML 可以包含完整可访问结构，但默认只展开当前、待处理和搜索命中的细节；哈希、环境 Manifest、Action payload/result 和插件权限置于折叠层。
- 隔离基准目标：100 枝干 / 300 Session 的项目页面服务端响应不超过 1.5 秒，Chromium `DOMContentLoaded` 不超过 2.5 秒，筛选/键盘选择反馈不超过 100ms。若共享 CI 明显抖动，记录原始值并以连续三次中位数判断。

## 本阶段诚实未知

- Git 图最终更适合纵向、横向车道还是可缩放画布；本候选先保留横向枝干关系，在窄屏改用纵向列表，并让用户凭真实任务判断。
- “像 VSCode”具体到多像：本阶段借用资源管理器、活动时间线和主工作区的信息层级，不复制桌面 IDE 的密度和微小字号。
- 想法空间默认采用时间流还是关系图仍由第 1 项用户判断；项目工作台不能替用户提前锁定该选择。

## 已实现投影

- `goal-worksite-v2` 先给出五类指挥摘要和本地只读筛选，再将父子目标按稳定前序排列；Session 节点显示 HEAD、ActionRun、审核和 Integration 信号，URL 固定所选 Session。
- 工作现场从数据库权威记录批量读取 Git workspace、InputArtifact、RunnerJob/File、ActionRun/Event、ToolCall、ToolLease、Notification、Evidence、Contribution、ReviewGate 和 Integration；不存在的事实显示为空，不生成演示日志。
- 中央插件目录默认只展开名称、准确版本、状态、能力和工具；权限、Runtime、摘要与发布者继续折叠。网页只能形成持久安装请求，实际安装仍必须经过签名链。
- 多个 Proposal 超过四项时默认折叠，避免遮住目标图；手机把大图限制在可滚动窗口并自动定位当前 Session，使工作现场仍可立即抵达。

## 隔离性能证据

`scripts/test-workbench-large.sh` 每次从空 PostgreSQL 建立 100 条目标枝干、300 个 Session、20 个待定 Proposal、20 个 ReviewGate、10 个逻辑 Integration、14 个 ActionRun、9 个判断暂停和 7 个未读通知。2026-08-22 完整质量门中的最近一次实测：

- 三次暖机后 TTFB 为 `88.531ms / 77.865ms / 93.519ms`，中位数 `88.531ms`，预算 `1500ms`；
- Chromium `DOMContentLoaded` 为 `349.5ms`，预算 `2500ms`；
- 100 条枝干筛选反馈为 `47.3ms`，预算 `100ms`；
- 1440px 与 390px 均无页面级横向溢出，300 个 Session 保持完整 DOM、筛选和方向键/Enter 深链操作。

这些数值是本机隔离样本，不冒充服务器容量保证；脚本已进入完整质量门，每次运行都会重新测量并按预算失败。
