# Fudian 目标枝干核心 v0.1：无人值守执行计划

> 历史归档：本文保留当时的目标、过程或证据，不定义当前产品行为。

- 计划日期：2026-08-22
- 权威产品约束：[`docs/product-design.md`](../../../product/product-design.md)
- 执行方式：一个持久 Goal，按顺序完成有限里程碑
- 结束条件：全部质量门通过并生成可审查的早晨报告

## 总目标

在不破坏现有真实数据、不公开部署、不推送 GitHub 的前提下，将当前 Rust Fudian 建设成一个可运行、可测试、Git 管理的“目标枝干核心 v0.1”纵向版本。它必须证明以下语义可以真实跑通：

- 用户与 AI 形成并批准 BranchProposal；
- 一个目标对应一条 GoalBranch；
- Agent Session 是枝干上的主要节点；
- 同一枝干只有一个可写 Session；
- 拟分支、请求判断、异常暂停和拟合并具有严格状态；
- 拟合并被退回后可以在同一枝干创建下一 Session；
- 接受的 Contribution 可以安全回流父枝干；
- 插件、工具链和项目依赖版本按 Session 隔离并可复现；
- 文件可以安全导入当前 Session/目标枝干；
- 桌面和移动端都能操作上述流程。

## 安全边界

执行期间必须遵守：

- 不修改或迁移当前正在使用的真实 PostgreSQL 数据；
- 不删除 Docker 卷、备份、恢复归档或用户文件；
- 不绑定公开网络地址，不占用旧服务的正式端口；
- 不配置或推送 GitHub remote；
- 不使用私人凭据、付费 API 或真实 AI Provider；
- 不安装未经确认的系统级软件；
- 所有数据库端到端验证使用一次性隔离 PostgreSQL；
- 所有浏览器验证使用本地/一次性预览；
- 不把当前仍未确定的图形布局固化成不可替换领域语义；
- 遇到会扩大权限、触及真实数据或要求用户作产品判断的问题时停止，不自行猜测。

## 里程碑 0：安全基线与 Git

### 工作

- 检查现有文件、备份与运行服务状态；
- 创建覆盖构建输出、备份、恢复包、环境文件和本地数据的 `.gitignore`；
- 初始化本地 Git 仓库；
- 将恢复后的 Rust 基线与产品设计文档作为初始提交；
- 创建本阶段短期功能分支；
- 建立可持续追加的 `docs/overnight-progress.md`。

### 验收

- `git status` 干净且没有误纳入备份、秘密或大体积运行数据；
- 初始提交能够完整重建当前 Rust 源码；
- 不存在 remote；
- 当前真实服务和数据计数没有变化。

## 里程碑 1：领域与协议基线

### 工作

- 编写领域状态机和不可变量说明；
- 定义 BranchProposal、GoalContractVersion、GoalBranch、AgentSessionNode、Contribution、ReviewGate、ReviewDecision 与 Event；
- 定义拟分支、请求判断、异常暂停、拟合并、退回、接受、恢复和完成的合法转换；
- 定义插件 Manifest、EnvironmentManifest、ToolCall、ToolResult、ToolLease 与 InputArtifact 协议；
- 明确当前旧表与新模型的共存/迁移策略。

### 验收

- 每个状态转换都有输入、前置条件、输出、事件和幂等语义；
- 文档与 `product-design.md` 不冲突；
- 未锁定的 UI 问题保持为图投影层选择。

## 里程碑 2：数据库与领域实现

### 工作

- 添加只增不减的新迁移；
- 实现目标枝干核心 Rust 类型和校验；
- 实现目标契约版本、单写者约束和审核状态机；
- 实现不可变事件与请求幂等；
- 保留旧数据读取路径，避免破坏当前纵向版本。

### 验收

- 空 PostgreSQL 可以从零迁移；
- 带旧基线表的隔离数据库可以增量迁移；
- 非法转换、重复请求和第二个并发写 Session 被拒绝；
- 领域单元测试覆盖主要正常路径和拒绝路径。

## 里程碑 3：HTTP/API 纵向流程

### 工作

- 实现 BranchProposal 草拟、修订、批准和取消；
- 批准后创建 GoalBranch 与首个 AgentSessionNode；
- 实现 Session 状态、拟分支、请求判断、异常暂停与拟合并；
- 实现独立审核记录、用户接受/退回和下一 Session；
- 实现选择性 Contribution 回流与项目图快照；
- 提供 HTML 表单和 JSON API 的共同应用服务。

### 验收

- 真实 HTTP 端到端测试跑通“Proposal → 枝干 → Session → 拟合并 → 退回 → 下一 Session → 接受”；
- 子枝干不能绕过批准创建；
- 未接受的拟合并不改变父枝干；
- 所有写接口具备幂等标识和输入校验。

## 里程碑 4：中央插件与环境版本基础

### 工作

- 实现插件 Manifest 解析、校验、注册、查询和内容摘要固定；
- 实现按需发现的插件目录与详情接口；
- 实现 EnvironmentManifest 规范化与环境指纹；
- 实现 Tool Broker trait、无状态 ToolCall/ToolResult 和 ToolLease 协议；
- 实现一个不依赖外部软件的参考/模拟插件，证明临时执行、结果返回和审计链；
- 实现不同 Session 使用冲突依赖版本时的隔离测试。

### 验收

- 同名不同版本插件可以并存；
- `latest` 被解析成固定版本/摘要后不会漂移；
- 相同环境得到相同指纹，不同锁文件或工具链得到不同指纹；
- Session 无法修改全局插件或其他 Session 的环境；
- 工具结果绑定准确的 Session、环境、输入快照和产物。

## 里程碑 5：安全文件导入

### 工作

- 实现带大小限制的流式/分段上传基础；
- 使用服务器生成的存储 ID、SHA-256 与可信元数据；
- 实现 InputArtifact 暂存、授权读取和枝干 inbox 导入；
- 防止绝对路径、`..`、文件名冲突和压缩包路径穿越；
- 小文件可复制到 worktree，二进制/大文件保留为产物引用；
- 冻结的拟合并现场不能被上传内容改变。

### 验收

- 正常文本和二进制文件能够上传、下载和关联 Session；
- 路径穿越、超限、无效 Session 与冻结现场写入被拒绝；
- 文件哈希和下载内容一致；
- 重复请求不会制造重复逻辑产物。

## 里程碑 6：项目图与工作台原型

### 工作

- 保留老 Fudian 的纸张、黑白、酸绿色与紧凑工具感；
- 在项目主界面表达“枝干是目标、节点是 Session”；
- 点击 Session 可以看到目标、文件/产物、工具行动、浏览器/测试证据和审核记录；
- 提供 BranchProposal、请求判断、异常暂停和拟合并的可操作界面；
- 使用可替换图投影，不决定暂停/合并最终是否为主要节点；
- 桌面端提供完整工作台，小屏支持推进、上传和审核。

### 验收

- 真实纵向流程无需直接调用数据库即可从浏览器完成；
- 390px 小屏没有横向破坏核心操作；
- HTML 转义、CSP 和输入边界保持有效；
- 视觉结果留有截图，但不被宣称为最终设计。

## 里程碑 7：质量门、CI 与早晨交付

### 工作

- 增加 GitHub Actions 模板，但不连接远程仓库；
- 运行 rustfmt、Clippy `-D warnings`、全部单元/集成测试；
- 在一次性 PostgreSQL 中运行迁移和 HTTP 端到端流程；
- 构建生产 Docker 镜像并在隔离端口验证健康检查；
- 使用 Chromium 检查桌面和移动端关键页面；
- 审查 Git diff、迁移兼容性、秘密与大文件；
- 更新 README、架构/迁移状态和恢复说明；
- 生成 `docs/overnight-report.md`。

### 最终验收

- 所有本地质量门通过；
- 隔离端到端流程和生产镜像健康检查通过；
- 真实数据库、产物卷与原预览未被测试写入；
- Git 历史按里程碑可审查且工作树干净；
- 报告列出实现内容、验证证据、未完成事项、风险与建议下一 Goal；
- 不存在未说明的后台进程、临时数据库或公开监听端口。

## 进度与停止规则

- 每完成一个里程碑，先验证、记录、提交，再进入下一个；
- 一个非关键子项受阻时，记录证据并继续同一总目标内仍可安全完成的工作；
- 同一关键阻塞连续出现且无法绕过时，保留最后安全状态并报告；
- 全部最终验收通过后立即停止，不为了占用整夜继续扩张范围；
- 用户醒来后可以检查 Goal 状态、Git 历史、进度日志和最终报告。

## 明确非目标

- 真实模型调用与 Provider 选择；
- 真正的 C/C++、Python、Rust、Playwright 或 PPTMaster 运行插件；
- 生产级容器编排与多节点 Runner；
- 最终 UI 布局和想法一级空间；
- 公网发布、DNS、证书、账户或 GitHub 操作；
- 删除旧模型、旧表或恢复资料。
