# 脉图首版范围

脉图先实现一个个人可用的项目推进流程：从项目图启动真实任务，独立任务可以并行，每次执行留下成果和记录，后续任务能使用准确版本的成果继续工作。

## 产品与部署

采用 Rust、Axum、PostgreSQL、Git worktree 和网页界面，Docker Compose 管理本机运行环境。网页关闭与任务取消分别处理；需要电脑关机后继续执行时，把后台部署在持续运行的服务器上。

本次优先接通现有工作台和真实执行，前端框架迁移以明确收益为前提。Flutter 桌面客户端保留为后续选项。Docker 提供运行环境，实际并发由任务调度、模型额度和工具资源共同控制。

## 最小使用流程

用户输入目标和资料，确认任务范围与验收条件，在图上启动任务。后台读取指定材料、请求模型、执行获准工具、将结果交回模型，保存产物和检查记录，并更新节点状态。

每个任务至少显示目标、状态、等待原因、成果和下一步。点进任务能查看输入来源、历次尝试和采用决定。运行结束、验证通过和用户接受分开表达。

## 首轮验收

| 验收项 | 可观察的结果 |
| --- | --- |
| 一个真实任务 | 真实请求与工具操作形成项目文件或补丁，检查记录可以查看 |
| 独立任务并行 | 三个任务的实际执行时段有重叠，拥有独立输入、记录和工作区 |
| 依赖及时推进 | 只依赖 A 的任务在 A 满足条件后取得执行资格，无需等待无关任务 |
| 失败与重试 | 失败只阻塞依赖它的任务；重试增加尝试，旧成果保留 |
| 历史可理解 | 可以看到当时的输入、输出、检查和决定，而非只翻 Git 提交 |
| 页面与服务恢复 | 重开页面能恢复进度；服务中断后能识别中断与结果不确定的执行 |

三个任务只是验收规模。并发上限应可配置，同时遵守 Provider 的请求和 Token 限额与本机资源限制。

## 第一项真实使用任务

先用脉图自身的一个小功能验证执行，例如任务状态筛选。确定接口与验收条件后，分别形成实现、测试和说明，再由整合任务运行检查。编码任务使用独立工作区，后续输入绑定到明确的成果版本。

插件市场、多人协作、全媒体生成和额外通信渠道在出现实际使用需求后再安排。
