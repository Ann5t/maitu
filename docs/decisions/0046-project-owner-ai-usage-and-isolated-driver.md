# 0046：项目使用负责人连接并隔离 AI Driver

- 状态：Accepted
- 日期：2026-08-24
- 置信度：高

## 背景

AI 连接第一版属于个人账号，但项目可以有负责人和参与者。如果每次运行都使用点击按钮者的连接，同一项目会混合不同人的账单、模型配置和数据边界；如果改用实例共享凭据，又会违背个人连接的决定。负责人转交时，也不能继续在原负责人不知情的情况下消耗其额度。

Codex 的账号登录和 Pi 协议适配还需要一个轻量运行位置。把它装入每个 Session 会重复占用空间，把 Node 运行时和 Provider 变化直接塞入 Rust 应用容器又会扩大主服务边界。

## 备选方案

- 每次 AI 调用使用触发操作的参与者连接。
- 所有项目使用实例管理员提供的一套共享 AI 凭据。
- 项目固定使用负责人的个人连接，并在负责人转交时显式交接。
- Provider 适配器随每个 Session 安装、嵌入 Rust 应用容器，或作为共享的内部容器运行。

## 决定

### 项目使用哪一份连接

一个项目的 Agent 运行统一使用当前项目负责人的个人 AI 连接和能力配置。参与者在权限允许范围内发送消息或触发操作，不会因此改用参与者凭据。每次调用仍记录实际连接所有者、项目、Session 和触发者，但不记录秘密。

转交项目负责人时，系统立即阻止旧负责人连接发起新的 AI 调用和新行动。项目中正在执行的叶子 Session 到达各自安全边界后形成检查点，并以“负责人转交”结束当前工作轮次；新负责人确认自己的连接和能力配置后，在相同 GoalBranch 上创建后继 Session 继续。旧 Session 的模型快照和历史保持不变，不能原地换凭据。若新负责人尚未配置必需的文字能力，项目保持可查看并等待配置，不消耗旧负责人额度。

### 连接交互

Codex 连接在“设置 → 连接”中原地打开短小弹窗。第一版使用设备码流程：弹窗显示验证码、剩余时间和“前往 OpenAI”动作，服务器轮询授权结果；成功后自动回到已连接状态。用户不粘贴访问令牌，登录过程不跳转到另一张 Fudian 设置页面。失败或过期只显示重新登录，不退回到网页抓取、账号密码收集或完整 Codex 安装。

GPT Image 2 连接允许填写、测试、替换和删除个人 OpenAI Platform API Key。完整 Key 只在提交时出现；保存后界面仅显示连接状态、用户给出的名称、不可逆识别标记和最近测试结果，不提供明文查看或复制。测试失败不会保存为可用连接。

### AI Driver 部署边界

Pi Codex 连接组件放入单独的、固定版本的内部 `AI Driver` 容器。整套实例共享一个驱动程序运行副本，不为项目或 Session 重复安装。容器没有宿主端口，不接受浏览器直连，只位于应用与 Driver 的专用内部网络；不挂载项目仓库、worktree、Git/LFS 对象、数据库或服务器凭据目录。

Rust 服务是持久秘密和调用记录的唯一权威。Driver 每次只得到完成准确登录、刷新或模型请求所必需的临时凭据和明确请求内容；可以在当前操作期间持有内存状态，但不能建立自己的持久凭据库。刷新后的凭据必须返回 Rust 服务原子保存，日志不得包含令牌、API Key 或完整敏感请求。

Driver 只转换登录、请求和流式响应，不执行模型提出的文件、终端、浏览器或其他工具调用。工具请求必须回到 Rust Agent 核心，通过当前 Session 的权限与 Tool Broker 校验后才能执行。

## 影响

- 项目的 AI 费用和数据边界始终跟随单一负责人，不因参与者操作而隐式变化。
- 负责人转交会让活动工作产生新的 Session 节点，但这是明确的重新分配，不是崩溃恢复或审核退回。
- Codex 登录适合服务器、电脑和手机组合使用，不要求浏览器回调到用户设备上的本地端口。
- AI Driver 可以单独固定和升级版本，同时不污染 Rust 主服务或 Session 工具环境。
- Driver 仍会看到明确发给模型的请求内容；“不接触项目文件”表示没有任意文件系统访问，而不是模型不接收用户授权的上下文。
