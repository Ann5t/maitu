# 0041：账号一次性初始化且项目保持单一负责人

- 状态：Accepted
- 日期：2026-08-24
- 置信度：高

## 背景

账号和项目角色已经区分为实例管理员、项目负责人和参与者，但首账号怎样安全建立、管理员怎样交付新账号、负责人停用后运行中的项目怎样处理仍未确定。若公网测试入口上的任意访客都能抢先成为首个管理员，整套实例会立即失去控制；若一个项目同时存在多名最终决定者，也可能对同一候选作出相反决定。

## 备选方案

- 空实例允许第一个普通网页访客直接注册为管理员。
- 管理员自行设置并传递其他用户的永久密码。
- 一个项目允许多名负责人，任一人都能独立作最终决定。
- 使用一次性初始化与临时凭据，并在第一版保持一个项目一名负责人。

## 决定

空实例的首个管理员仍由首次注册建立，但注册必须同时提交部署时由 Fudian 初始化命令生成的一次性初始化码。浏览器页面和远程 API 不展示或重新读取该码；服务器只保存能够验证它的摘要。首账号创建与初始化码消费在同一数据库事务中完成，成功后永久关闭公开注册并销毁未使用的明文码。

后续账号只能由实例管理员创建。创建时系统生成一次性临时密码，只向管理员显示一次；服务器只保存密码摘要。用户首次成功登录后只能完成密码修改和必要的账号确认，在设置自己的新密码前不能进入想法、项目或后台。管理员可以在旧临时密码泄露或遗失时废止并生成新的临时密码，旧值立即失效。

第一版每个项目在任一时刻恰好有一名负责人。创建者是初始负责人；负责人可以把职责明确转交给一个现有参与者，管理员也可以通过已有的审计接管机制成为负责人。转交在一个事务中改变角色并记录操作者、前后负责人、原因和时间，不存在两个负责人同时拥有最终决定权的中间状态。已经形成但尚未决定的 Proposal、MergeGate 和完成候选转由新负责人处理，准确历史决定仍保留原操作者。

停用账号会立即撤销其所有登录会话并拒绝新登录。若该账号只是参与者，停用不删除其消息、文件、决定或其他历史产出，也不自动暂停项目。若它是项目负责人，相关项目不再派发新的 Agent 行动；正在执行的不可分割行动到达最近安全检查点后暂停。管理员先为每个受影响项目指定新负责人，再显式恢复。停用本身可由管理员撤销，但恢复账号不会自动恢复项目或夺回已经转交的负责人身份。

删除账号不属于第一版普通操作；需要停止访问时使用可恢复的停用，以免破坏历史 Actor、审计和项目来源。

## 影响

- 公网 IP 验收期间，扫描到入口的陌生人不能仅靠抢先访问取得管理员权限。
- 管理员不需要知道或长期保存其他用户的正式密码。
- Proposal 和 MergeGate 始终只有一个明确的人类最终决定者。
- 负责人账号停用不会让后台 Agent 在无人负责的项目中继续消耗资源，也不会删除可追溯历史。
- 多负责人、邀请链接、自助注册和账号硬删除不属于第一版。
