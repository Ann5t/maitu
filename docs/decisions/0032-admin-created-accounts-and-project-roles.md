# 0032：管理员创建账号且项目区分负责人和参与者

- 状态：Accepted
- 日期：2026-08-24
- 置信度：高

## 背景

当前实现把账号固定为唯一的 `id=1`，所有登录请求都代表同一个 Owner。目标产品需要让服务器管理员为其他人开设账号，同时避免每个账号看见全部私人想法、任意批准别人的目标或修改整台服务器的 AI 与插件配置。

## 备选方案

- 永久保持单用户，其他人共享同一账号。
- 所有账号看见全部内容并拥有相同权限。
- 区分实例管理员、普通账号和项目成员角色。

## 决定

空实例只允许一次原子化的首账号注册；成功者成为实例管理员。首账号存在后关闭自行注册，后续账号只能由管理员创建。

每个账号拥有自己的想法空间。项目默认只对创建者和被加入该项目的账号可见，创建者成为初始项目负责人。项目成员先只使用两种角色：

- **负责人**：接受 ProjectProposal 或 BranchProposal、决定 MergeGate、确认项目完成、管理项目成员及项目设置。
- **参与者**：查看工作现场、聊天、上传文件并推动 AI 形成或修订 Proposal，但不能替项目作最终接受、合并或完成决定。

实例管理员负责账号、AI 连接与配置、插件、服务器预算、备份和其他全局后台设置。管理员能够查看整套实例中的项目并处理故障，但管理员身份本身不能伪装成项目负责人作决定；需要推进或决定某个项目时，必须执行明确的接管操作，留下操作者、时间、原角色与新角色的审计记录。

所有人工 Proposal、MergeGate、项目完成、成员和设置决定都绑定准确账号以及决定当时的权限。账号创建凭据、首次改密、停用后的运行任务处理，以及一个项目能否有多名负责人，留给账号实现前继续确定。

## 影响

- 不再把目标产品称为单用户系统，当前唯一账号 schema 需要在正式测试前干净重建。
- 普通账号不会自动看到其他人的想法和项目。
- 服务器管理权与项目内容决定权分开，管理员介入不会丢失责任来源。
- 第一版没有自助邀请注册、公开注册或复杂自定义权限表。
