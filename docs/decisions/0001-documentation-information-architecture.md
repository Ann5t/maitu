# 0001：按用途组织工程文档

- 状态：Accepted
- 日期：2026-08-24
- 置信度：高

## 背景

原 `docs/` 同时平铺产品基线、当前实现、API 参考、运维命令、BranchProposal、夜间执行日志和验收报告。读者无法只凭文件位置判断内容是否仍然有效，根 README 也承担了过多细节。

## 备选方案

- 继续平铺，以文件名前缀和版本号区分。
- 按实现阶段或日期分目录。
- 按读者用途区分产品、架构、参考、运维、开发、决策和历史。

## 决定

采用按用途组织的目录。当前说明与历史记录分离；根 README 只负责定位、启动、检查和导航；重要且难以逆转的决定使用追加式 ADR；Cargo、测试、迁移和 Compose 的工具惯例位置保持不变。

## 影响

- 读者可以先判断文档用途和状态，再决定是否读取。
- 历史证据继续保留，但不会冒充当前规范。
- 文件移动必须同步修复相对链接，并由自动检查阻止死链。
- 后续新增文档需要先选择所属类别，不能重新堆放到 `docs/` 根目录。
