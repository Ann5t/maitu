# 0005：获批子枝干立即合入父枝干

- 状态：Accepted
- 日期：2026-08-24
- 置信度：高

## 背景

多个兄弟目标从父枝干同一安全点并行后，可能在不同时间完成。若已经接受的子枝干仍等待所有兄弟结束，父枝干长期不能反映权威结果，也无法让其他工作及时利用该成果；推迟合并仍不能消除后续 Git 冲突。

## 备选方案

- 等所有兄弟枝干结束后批量合并。
- 子枝干获批后立即合并，其他兄弟保留原基线。
- 合并一个子枝干后自动更新所有兄弟枝干。

## 决定

兄弟子枝干只在没有已知前置依赖时并行。任一子枝干通过审核并由用户接受后，立即以标准 Git merge 合入直接父枝干，不等待其他兄弟完成。

仍在运行的兄弟枝干保持创建时的 Git 基线；系统不得因父枝干前进而自动 rebase、reset 或 merge 它们。父 Git branch 由受控整合流程推进，父工作 Agent 继续等待，因此不违反仅叶子执行规则。

若开始前已知 B 依赖 A，B 不应与 A 成为并行兄弟，而应在 A 返回后创建。运行中才发现的新关联，通过后续的父更新通知和显式同步机制处理。

## 影响

- 用户接受与父枝干权威状态保持一致，不增加“已接受但长期未合并”的中间状态。
- 后合并的兄弟可能面对父枝干已经变化产生的正常 Git 冲突；推迟合并也无法从根本上避免这一点。
- 其他兄弟如何发现、读取或同步新的父成果必须单独设计；自动修改其工作区被明确禁止。
