# 0042：Session 固定 AI 配置且第一版不自动换模型

- 状态：Accepted
- 日期：2026-08-24
- 置信度：高

## 背景

AI 连接与七类模型能力已经分开配置，但尚未确定同一能力有多个模型时怎样选择、设置变化是否影响正在运行的 Session，以及服务不可用时是否自动换模型。隐藏切换会使同一 Session 的行为难以理解，也可能在用户不知情时换用能力、价格或数据边界不同的服务。

云服务还可能让一个未带日期的模型名称指向后续版本。Fudian 无法把服务商没有公开的版本信息凭空变成可复现事实，但应准确记录当时能够观察到的身份。

## 备选方案

- 每次调用都让 Agent 从所有同能力模型中动态挑选。
- 为每项能力设置自动备用链，故障时无提示切换。
- 每项能力只选择一个当前模型，Session 固定配置，模型不可用时暂停。

## 决定

管理员可以登记多个模型配置，但实例的每项模型能力至多选择一个默认模型。项目默认继承实例选择；项目负责人可以从管理员已启用且声明对应能力的模型中为项目改选。未配置的可选能力明确显示不可用；文字能力必须配置后才能启动 Agent Session。同一个模型仍可同时声明多项能力。

每个 Session 启动时保存一份不可变的 AI 配置快照，包括所选连接和 Provider 模型 ID、能力映射、可公开参数、上下文与输出限制，以及这些配置的版本和内容摘要；认证秘密不进入快照。项目或实例设置之后发生变化只影响新 Session，不会让运行中的 Session 静默更换模型。

第一版不建立备用模型、自动故障转移或 Agent 自主改选同能力模型。连接超时、限流或服务不可用可以按照调用本身的安全规则有限重试；仍不可用时，当前 Session 在安全检查点暂停并通知用户。模型拒绝、内容限制或回答质量不佳同样不能通过隐藏换模型绕过。管理员因泄露或安全原因停用连接时立即阻止新调用，引用该连接的 Session 随后暂停。

每次 AI 调用自动记录实际连接、请求的 Provider 模型 ID、非秘密参数、能力、来源 Session、配置快照摘要、用量，以及服务响应中提供的准确模型版本、修订或系统指纹。本地模型和可下载权重记录内容摘要。若云服务只返回可能漂移的别名、没有提供不可变版本，记录必须明确标为“服务商未提供可固定版本”，不能宣称该次结果能够完全复现。

## 影响

- 用户看到的项目模型选择与 Session 实际使用一致，不会在后台突然换模型。
- 更改默认模型需要等到新 Session 才生效，但正在工作的上下文更稳定、审计更清楚。
- 单个 Provider 故障会暂停相关 Session；第一版用可见失败换取较小的配置和行为复杂度。
- 将来若真实使用证明需要备用链，必须另行决定允许切换的条件、顺序、成本与数据边界，不能直接在现有字段中偷偷开启。
- 云模型的可复现程度由 Provider 实际提供的信息决定，Fudian 只保证如实记录。
