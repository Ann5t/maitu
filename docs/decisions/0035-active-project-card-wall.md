# 0035：项目首页使用活跃项目卡片墙

- 状态：Accepted
- 日期：2026-08-24
- 置信度：高

## 背景

一个项目可以同时存在正在运行、等待用户、排队和准备合并的不同目标枝干，因此把整个项目强制放入“运行中、排队中、等待我”某一状态列会丢失事实。现有项目首页还铺有总数统计、单独的成果入口和较多说明，不能直接回答用户最关心的“各项目现在在做什么”。

## 备选方案

- 项目按一个汇总状态进入互斥看板列。
- 使用传统统计仪表盘和完整项目清单。
- 使用可排序的活跃项目卡片墙，并在卡片内轮换枝干现状。

## 决定

登录后的默认入口是“项目”。主界面只显示仍在推进的项目，采用紧凑、可拖拽排序的卡片墙，不设置互斥状态列。暂停、完成和归档项目进入独立“历史”入口，可以查看和按其领域规则恢复或继续来源工作。

项目卡首层只保留：

- 固定项目名称；
- 轮换显示各个未结束 GoalBranch 的“枝干名称 · 当前动作或等待状态”；
- 正在运行数与待用户处理数。

轮换信息由真实枝干、Session、Proposal 和 MergeGate 状态派生，不建立项目级“当前进度”权威对象。轮换使用克制的位移或淡入淡出，悬停、键盘聚焦或用户与卡片交互时暂停；系统启用减少动态效果时不自动轮换，并提供手动切换或稳定摘要。

点击项目卡回到该用户上次查看的 Session 工作现场；第一次进入时定位当前最需要关注的节点，没有待处理项时定位一个运行中的执行前沿。

“待我处理”作为全局通知入口汇总 Proposal、MergeGate、Session 暂停和工具请求等真实来源，点击条目直接到达对应现场，不成为第三个一级空间或复制一套待办状态。全局“成果”入口删除；文件和成果只在所属项目现场中查看。

## 影响

- 一个项目可以同时表达多条枝干的不同状态，不需要伪造单一项目状态。
- 首页不再用统计面板和长说明占据主要空间。
- 动态摘要帮助用户快速巡视项目，仍满足键盘和减少动态效果需求。
- 当前项目统计条、成果视图和独立待处理一级导航属于待替换界面。
