# 0023：Session 继承精简上下文并在安全边界接收消息

- 状态：Accepted
- 日期：2026-08-24
- 置信度：高

## 背景

同一枝干可能经历多个 Session，一个项目也可能同时存在多个活动子目标。把所有旧对话和所有枝干内容塞入每次模型调用会浪费上下文并引入无关信息；只给一段摘要又可能让 Agent 忘记硬约束或无法回查原始决定。

用户还需要在 Agent 工作时继续发消息或暂停。若消息只能等 Session 结束才读取，交互过慢；若在文件写到一半时强行改变执行，又可能留下损坏现场。

## 备选方案

- 每个新 Session 自动装入全部历史对话和整个项目内容。
- 新 Session 只接收一段不可追溯摘要。
- 默认装入最低充分上下文，完整来源永久保留并按需读取。
- 用户消息立即中断任意工具动作。
- 用户消息只在整个 Session 结束后生效。
- 普通消息在下一个安全动作边界交付，暂停先形成可恢复检查点。

## 决定

同一 GoalBranch 创建下一 Session 时，完整旧对话、文件和来源记录继续持久保存。默认上下文只装入当前目标说明、全部硬约束和权限、已确认决定、上一 Session 交接摘要、相关项目文件及当前未决事项。Agent 可以通过受审计的按需读取回到完整旧消息、文件和 Evidence；摘要与索引都是可重建入口，不替代原文。

每个 Session 都能看到项目目标枝干地图中的名称、父子关系、状态和简短进度，并能读取已经审核 merge 后进入其祖先项目状态的成果。活动兄弟枝干的未审核文件、完整对话和临时结论不自动共享，也不能被直接修改。地图摘要是被动工作状态，不等同于此前搁置的 Coordinator Agent、点对点跨枝干 Signal 或自动成果广播。

Session 运行期间，用户普通消息写入持久输入队列，在 Agent 完成当前不可分割动作并到达下一个安全边界时交付。用户发出“立即暂停”时，执行器要求当前行动尽快保存文件状态、形成 Git 检查点和恢复说明，再把同一个 Session 置为手动暂停；恢复继续该 Session，不因进程重启制造新节点。

## 影响

- 新 Session 保持连续性，但模型窗口不会随项目寿命无限膨胀。
- 用户可以从摘要逐层追到准确原文，不依赖 AI 记忆猜测。
- Agent 对项目全局进度有基本方向感，同时未审核兄弟工作仍保持隔离。
- 普通反馈能够较快生效，暂停也保留可恢复现场；执行器必须定义工具动作的安全边界、检查点和协作取消超时。
- 当前上下文实现中依赖 GoalContract、Contribution、Artifact 和 AttentionItem 的目录类型，需要在正式测试前的干净重建中替换为已接受目标模型。
