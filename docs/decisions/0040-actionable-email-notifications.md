# 0040：邮件只发送需要处理的通知

- 状态：Accepted
- 日期：2026-08-24
- 置信度：高

## 背景

Fudian 在服务器上持续推进工作，用户可能已经关闭网页或正在使用另一台设备。只显示站内“待我处理”会让重要审批和故障长时间无人看到；把每条 Agent 进度都发到邮箱又会迅速形成噪音，使真正的阻塞被忽略。

通知不能成为另一套任务状态。Session、BranchProposal、MergeGate 和运维故障仍是权威来源，邮件只负责把用户带回对应现场。

## 备选方案

- 第一版只提供站内通知。
- 将所有 Agent 进度和完成消息都发送邮件。
- 只为需要人工决定或无法自行恢复的状态发送去重邮件。

## 决定

电子邮件是第一版唯一的站外通知渠道。管理员在“设置 → 连接”中配置实例级 SMTP 发件连接，包括服务器、端口、传输安全、认证、发件身份和测试动作；密码只保存在服务器秘密存储中。每个账号保存自己的收件邮箱。项目决定发给当时有权处理该来源的项目负责人，实例证书、备份、安全和关键服务故障发给实例管理员。

以下状态可以触发邮件：等待用户回答的 Session、待决定的 BranchProposal、MergeGate 和项目完成确认，以及系统无法自行恢复的 AI、资源、证书、备份、安全或关键服务故障。普通 Agent 进度、排队、自动重试、测试日志和无需人工处理的阶段完成不发送邮件。

同一“来源对象 + 状态版本”立即发送一次；24 小时后仍未解决时只再提醒一次，此后不循环发送。来源进入新状态或形成新版本后才获得新的通知身份。SMTP 的暂时失败可以在相同幂等键下有限重试，不得因此生成多封逻辑相同的邮件。

邮件正文只包含项目或实例名称、枝干或来源、简短原因、需要用户做什么，以及指向精确 HTTPS 现场的深链接。完整对话、项目文件、终端输出、密钥、令牌和其他敏感内容不进入邮件。点击邮件只负责打开来源；任何接受、合并、继续或接管仍需登录后在 Fudian 内明确执行。

站内等待状态不依赖邮件是否成功。系统通过 outbox 保存通知意图、幂等身份、尝试和投递结果；SMTP 配置失效时，相关运维故障仍显示在管理员的站内待处理入口。

## 影响

- 用户离开网页后仍能及时看到真正需要介入的节点。
- 固定的一次通知和一次提醒避免长期枝干反复轰炸邮箱。
- 多账号部署需要维护准确的账号邮箱与项目负责人关系。
- 邮件服务本身故障时不能保证站外告警，因此站内来源状态和部署侧健康监控仍不能省略。
