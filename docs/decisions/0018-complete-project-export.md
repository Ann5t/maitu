# 0018：单项目导出包含完整持久工作现场

- 状态：Accepted
- 日期：2026-08-24
- 置信度：高

## 背景

项目 GitHub 仓库用于保存和协作项目文件，但 Fudian 还在 PostgreSQL 中保存目标枝干、Session、对话、Proposal、Evidence、MergeGate 和决定历史。把这些状态自动写入 GitHub 会混淆项目同步与软件运行数据备份，也可能意外公开工作过程。

用户接受服务器在没有备份时损坏会造成数据丢失，但需要能够把一个项目显式导出为文件，并在另一套 Fudian 中完整恢复。需要确定这种导出只带项目文件，还是连同整个工作现场一起带走。

## 备选方案

- 只导出项目默认 branch 和 Git LFS 文件，工作流状态不保证恢复。
- 项目文件进入 GitHub，Fudian 状态自动进入同一仓库的隐藏 branch。
- 显式生成包含该项目全部持久内容的独立备份文件。

## 决定

“导出项目”生成一个版本化、可校验的单文件备份，并完整包含该项目的：

- Git 仓库必要 refs、commit 与 Git LFS 对象；
- GoalBranch 图、目标说明各版本与状态；
- Session 全部内容和完整对话；
- Proposal 各版本、用户决定和来源；
- Evidence、MergeGate、审核、暂停、恢复及事件历史；
- 插件和环境版本清单、内容摘要及其他不可重建的项目级持久记录。

导入必须在新 Fudian 实例中恢复这些内容之间的引用和顺序。项目备份不包含账号密码、登录会话、API 密钥、GitHub 凭据等秘密，也不包含缓存、临时上传、运行进程和可重新取得的工具二进制；恢复后由新实例重新绑定账号和外部凭据。

运行中的项目可以请求导出，但导出器必须先等待所有项目写入到达可恢复的安全检查点，再短暂冻结该项目，从 PostgreSQL、Git 和 Git LFS 取得一致快照。备份文件通过完整性校验后自动解除冻结并从原检查点继续工作；导出失败也必须解除冻结并保留可见原因。任何跨存储阶段不一致的半成品都不能标记为有效备份。

项目 GitHub 远端继续只承担该项目的常规 Git/Git LFS 同步。Fudian 不为备份创建隐藏状态 branch，也不自动把对话和审批记录推送到远端。没有有效项目导出或另行建立的实例备份时，服务器故障后的运行数据不保证恢复。

## 影响

- 单项目导出是完整、可迁移的项目工作现场，不是普通源码压缩包。
- 导出器必须从 PostgreSQL、Git 和 Git LFS 取得一致快照，并用清单和校验值拒绝不完整备份。
- 运行中导出会造成一次短暂且可见的项目级写入冻结，但不会要求用户手动停止或重新启动 Session。
- 导入器需要处理格式版本、身份重建、引用校验以及外部凭据重新绑定。
- 普通 GitHub 推送不会泄露 Fudian 对话与内部审批历史。
- 整实例自动备份、备份加密、导入时的项目重名策略和保留周期仍可分别设计。
