# 0024：统一工具目录复用不可变资源并隔离 Session 环境

- 状态：Accepted
- 日期：2026-08-24
- 置信度：高

## 背景

大量项目和 Session 会重复使用相同版本的 Rust、Python、GCC、Node、浏览器和第三方库。每个 worktree 都重新下载一套会浪费磁盘与时间；把所有 Session 接到一个可变的全局环境又会产生依赖冲突和相互污染。若每次简单命令都冷启动完整容器，逻辑虽然干净，交互速度也可能无法接受。

插件还同时涉及 AI 使用说明、结构化工具、模板和运行环境。把编译器版本、Python 库和 PPTMaster Skill 强迫成完全相同的包，会让调用与版本管理变得僵硬。

## 备选方案

- 每个 Session 在自己的 worktree 中下载并安装完整工具链。
- 所有 Session 共用一个可以被任意修改的大环境。
- 每次调用都创建冷 Worker，绝不复用运行进程。
- 统一目录管理能力与资源，按内容去重不可变数据，为 Session 建立隔离视图并允许短期热 Worker。

## 决定

用户和 Agent 只看到一个统一工具目录。底层区分版本化环境资源与插件能力：编译器、运行时、包和浏览器层属于可复用资源；插件描述 Agent 能做的操作，并可以包含 Skill、结构化接口、Assets、Tests、可选专用 Runtime 及所需资源声明。

同一内容摘要的编译器、包和不可变运行层在服务器上只保存一份。每个 Session 固定自己的不可变 EnvironmentManifest，并通过只读引用或隔离视图组合所需版本；不同环境不能共享可变 home、进程、安装目录或临时构建状态。

项目新增普通依赖时，Agent 修改仓库中的正式依赖声明和锁文件，中央环境管理器解析、下载或复用内容并生成新的环境版本。Agent 不在 worktree 中运行裸安装命令，也不能自行改变服务器平台工具。缺少新的插件或平台能力才进入中央安装请求流程。

工具 API 对 Agent 保持逻辑无状态，每次调用都固定输入、worktree 基线、EnvironmentManifest、权限和结果。Broker 为降低启动延迟，可以复用一个仅属于该 Session 和准确环境指纹的热 Worker；它具有短期空闲期限，环境变化、Session 结束、异常或超时后销毁。任何未写入项目文件、EnvironmentManifest 或正式运行记录的 Worker 内部状态都不能影响可恢复性。

Session 默认只获得插件 ID、名称和一句能力摘要。Agent 选择能力后才按需读取准确版本的 Skill、工具参数和参考资料；未选择插件的完整说明不进入模型窗口。

## 影响

- 相同工具和依赖不因项目数量线性重复占用磁盘。
- Python 或其他库版本互相冲突的 Session 可以同时运行，不修改彼此环境。
- 热 Worker 改善连续命令和交互工具的延迟，同时保持可销毁和可重建。
- 实现需要内容寻址存储、环境垃圾回收、只读复用边界、Worker 租约和环境指纹校验。
- 具体采用 OCI layer、包管理器缓存、Nix 风格 store、overlay 或其他组合仍需以原型性能和兼容性决定，不能提前绑定为产品概念。
