# 0029：服务器持续执行且等待只阻塞相关枝干

- 状态：Accepted
- 日期：2026-08-24
- 置信度：高

## 背景

Fudian 的 Session 和调度状态本来就持久存在于服务器。若再增加“过夜模式”，会让用户误以为关闭浏览器通常会停止 Agent，也会增加一套与正常后台执行重复的开关和状态。

无人查看时真正影响利用率的是：一条枝干等待用户是否会停止全部项目、用户能否在离开前批准多个已知并行目标，以及失败行动是否可以安全重试。

## 备选方案

- 只有打开网页或启用过夜模式时 Agent 才运行。
- 任一枝干等待用户就暂停整个项目。
- AI 在无人值守时可以自行批准新 BranchProposal。
- 已批准 Session 持续运行，等待局部阻塞，其他合格叶子继续调度。

## 决定

Fudian 不建立“过夜模式”业务概念。已经批准且可运行的 Session 默认由服务器持续推进，浏览器关闭、客户端断线、电脑休眠或用户换设备都不改变执行状态。Session 只因拟合并、BranchProposal 审批、用户判断、异常、全局资源边界或用户主动暂停而停下。

等待状态只阻塞它所属的 GoalBranch。其他已经批准、没有依赖阻塞且资源允许的叶子 Session 继续运行；调度器在没有任何合格工作时进入空闲等待，不创建虚假任务维持利用率。

父 Session 可以在用户离开前提出多个独立 BranchProposal。界面允许逐个接受，也允许用户一次接受明确选中的准确当前 revisions，但每条 Proposal 仍分别保存身份、目标说明、来源和人工决定，不增加 ProposalBatch 对象。运行期间新发现的分支一律等待用户，AI 和调度器无权代为批准。

自动重试只适用于已声明并能够验证为幂等或无外部副作用的行动，并具有有限次数和退避。网络响应不明的发送消息、部署、付费及其他外部写操作不得盲目重放；对应 Session 保存检查点、进入等待并通知用户。

## 影响

- 用户可以关掉设备，服务器继续完成所有已经授权的工作。
- 单个判断点不会浪费其他独立枝干的可用执行时间。
- 想提高长时间无人值守利用率，应在离开前审阅足够的并行 BranchProposal，而不是放弃分支前人工边界。
- 批量接受只是交互便利，不破坏每个目标枝干的独立目标说明与审计。
- 调度器需要按枝干依赖、等待来源、资源和重试安全性计算可运行集合。
