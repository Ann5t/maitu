# 0044：第一版只提供单项目导出导入

- 状态：Accepted
- 日期：2026-08-24
- 置信度：高

## 背景

单项目完整导出已经能够携带项目 Git/Git LFS、目标图、Session、对话、Proposal、Evidence 和审核历史。继续为第一版设计整实例定时备份、备份目的地、实例恢复密钥、增量保留和整机切换，会形成一套独立且较大的运维产品。

用户接受当前服务器损坏时未导出的数据可能丢失，希望先把可理解、可移动的单项目文件做好，而不是同时维护整机灾难恢复系统。

## 备选方案

- 第一版同时提供项目导出和整实例自动备份。
- 只依赖项目 GitHub 仓库，不保存 Fudian 工作现场。
- 第一版只提供完整的单项目导出与导入，整实例备份明确延期。

## 决定

第一版只提供已经定义的单项目导出与导入。每个有效导出文件完整保存该项目的项目文件和 Fudian 工作现场，并按既定规则加密、校验、处理运行中一致快照和同源项目导入；它仍不携带账号密码、登录会话、AI/API 密钥、GitHub 或 SMTP 凭据。

Fudian 第一版不提供整实例备份页面、自动备份计划、备份目的地管理、整机恢复密钥、全实例恢复或备份保留策略。也不把多个项目导出暗中包装成一套具有实例恢复承诺的“批量备份”。部署者自行使用磁盘快照、主机备份或其他基础设施能力时，那是 Fudian 产品合同之外的运维措施。

服务器损坏后，管理员重新部署空实例、建立账号和外部连接，再逐个导入仍然持有的项目文件。账号、尚未立项的 Idea、实例设置、插件安装状态、连接秘密、临时运行材料，以及各项目最后一次导出之后的新状态都可能丢失。GitHub 只恢复项目普通 Git/Git LFS 内容，不能代替包含对话和审核状态的 Fudian 项目导出。

升级界面应明确提示先导出重要项目，但不声称已经自动保护整台实例。正式测试后的数据库变化必须继续使用经过验证的前向、兼容迁移；旧应用回退不能执行 schema downgrade。若某次升级无法在没有整实例快照的情况下提供可接受的安全边界，该升级必须延期，或由部署者明确提供产品外的基础设施快照后再执行。

当前仓库已有的整实例备份与恢复脚本属于现有实现和开发运维事实，本决策不把它们解释成第一版产品能力，也不授权在没有确认用途和现场数据的情况下删除它们。目标模型干净重建时只需验收单项目导出导入合同。

## 影响

- 第一版少一套复杂的自动备份、密钥和远端存储管理界面。
- 用户能以项目为单位迁移完整工作现场，但必须主动、及时导出。
- 一次服务器故障不能保证恢复账号、Idea、全局配置或最新未导出工作。
- 数据库升级需要保持更严格的前向兼容和旧应用可读边界。
- 将来若真实使用需要整实例灾难恢复，必须作为独立产品决策重新设计。
