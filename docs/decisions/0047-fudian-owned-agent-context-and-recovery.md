# 0047：Fudian 持有 Agent 上下文并从完整步骤恢复

- 状态：Accepted
- 日期：2026-08-24
- 置信度：高

## 背景

Provider 保存的响应、线程和缓存可能过期、丢失或因更换连接而不可用，Fudian 不能把项目继续运行的能力寄托在外部会话上。

一个长 Session 还可能超过模型上下文窗口。系统既不能永远重发全部历史，也不能简单删除最旧内容并冒险丢失目标、权限或硬约束。模型输出流或服务进程中断时，恢复还必须避免重复执行已经成功的工具和不确定的外部副作用。

## 备选方案

- 以 Provider 的远端线程为上下文权威，Fudian 只保存结果。
- 每次发送全部历史，超过窗口后直接丢弃最旧消息。
- Fudian 保存完整历史，并用可追溯的版本化压缩构造模型上下文。
- 中断后重放整个 Session，或只从最后一个持久完成步骤继续。

## 决定

### 上下文权威

Fudian 的数据库与项目持久存储是 Agent 记忆的唯一权威。每次对话、选中的上下文来源、模型输出、工具请求、工具结果、用户追加消息、暂停和完成状态都追加保存。

Provider 的线程、响应 ID 和提示缓存只用于加速或辅助恢复。Driver 或 Provider 状态丢失时，Fudian 使用 Session 事件、`ContextSnapshot`、准确文件和工具结果重建输入，并继续同一个 Session；系统不能把只存在于 Provider 端的隐藏历史当作已经保存的项目事实。

### 长上下文压缩

完整原始对话和来源始终保留。接近模型安全上下文预算时，系统在同一 Session 内自动生成一个版本化压缩检查点，不逐次要求用户批准，也不因此创建新 Session。

压缩检查点记录覆盖的准确事件范围、来源与结果哈希、生成方式、模型和配置。当前目标、祖先硬约束、权限、当前状态与未解决事项始终以完整形式进入上下文，不能只由摘要替代。更早的对话和工具日志可以压缩，但摘要必须带来源，Agent 能按需读取原始内容。

如果不可压缩内容与当前最小输入仍然超出模型窗口，Session 必须暂停并说明原因，不能静默删除约束后继续。

### 中断与恢复

流式输出中断时，已经到达界面的片段保存为“不完整输出”。它只供用户查看和故障诊断，不能成为完整 Agent 消息、决定、工具授权或拟合并依据。

恢复从最后一个持久完成的 Agent 步骤继续。系统先利用 Provider 响应标识或幂等信息查询已经存在的结果；无法确认时，以明确的重试身份重新请求。已经持久记录为成功的工具动作不能因为模型重试而再次执行，安全或幂等动作由 `ActionRun` 状态控制。

发送、付款、部署和私有外部写入等副作用如果无法确认是否成功，Session 必须暂停等待核验。单纯的应用、Driver 或 Provider 崩溃不会创建新 Session。

### 用户可见性

每次模型调用保存一份不含秘密的上下文清单，包括目标版本、消息范围、摘要版本、文件与来源引用、模型公开参数、Driver 版本和工具目录版本。

界面默认只显示类似“目标 v3、4 个文件、2 项决定”的简短概括；展开后可以检查准确来源与规范化后的模型输入。认证令牌、API Key 和 Cookie 永远不进入清单、项目导出或可展开内容。

## 影响

- 应用、Driver 或 Provider 重启后仍可从 Fudian 的持久状态继续工作。
- 长项目保留完整历史，同时不要求每次把全部内容塞入模型窗口。
- 需要为原始事件、压缩检查点和调用清单增加数据库或对象存储空间；这些内容随完整项目导出。
- 不完整输出不能驱动工具，因此极端情况下可能产生一次额外模型重试费用。
- Provider 缓存只能改善性能，不能成为恢复正确性的前提。
