# 0025：管理员安装插件且 Session 固定工具版本

- 状态：Accepted
- 日期：2026-08-24
- 置信度：高

## 背景

中央工具系统同时服务多个项目。Agent 给项目增加普通依赖与给整台服务器安装 Blender、PPTMaster 或新的运行能力，影响范围并不相同。前者是项目工作的一部分，后者会消耗共享磁盘并扩大供应链和权限边界。

插件升级如果直接替换运行中版本，也会让同一个 Session 在没有修改代码的情况下出现不同结果。另一方面，把每次工具调用、版本和参数都铺在主界面上，又会违背渐进式披露原则。

## 备选方案

- Agent 可以自行安装任意服务器级工具，之后再记录。
- 所有安装和每一次普通调用都请求用户批准。
- 管理员批准新增平台能力，已授权 Session 内自由调用。
- 更新插件时原地覆盖旧版本。
- 不可变版本并存，Session 固定准确版本。

## 决定

新增或安装服务器级插件、专业软件和平台工具只能由管理员批准。Agent 在原 Session 对话中提出安装卡，至少简要显示准确版本、来源、预计大小、所需权限和当前用途。项目依赖文件中新增的普通语言库由环境管理器自动解析，不进入管理员插件审批。

插件已安装且能力已包含在当前 Session 的获批权限后，Agent 可以重复调用编译、测试、公开网络读取和当前 worktree 操作，不逐次询问。私人账号登录、发送消息、部署、付费和其他外部写入仍要求单独授权；安装插件本身不授予这些权限。

插件版本与内容摘要不可原地覆盖。升级安装为并列新版本，运行中 Session 继续固定旧 EnvironmentManifest；新版本只供新 Session 或经过用户接受的环境修订使用。管理员可以停用旧版本以阻止新选择，但仍由活动或可恢复环境使用的运行资源不能直接清理。

主工作现场只显示当前工具名称、动作、状态和必要进度。完成后的版本、参数、日志、耗时、文件输出和 Evidence 默认折叠在运行记录中。版本占用、引用者、更新、停用和清理入口集中放在设置页，不创建持续可见的复杂工具调用图。

## 影响

- Agent 日常开发不会被逐次审批打断，新平台能力仍受共享服务器管理边界控制。
- 工具升级不会静默改变运行中 Session 的结果。
- 主界面保持简洁，同时调试、复现和磁盘管理仍有准确来源。
- 需要实现安装请求卡、不可变版本索引、EnvironmentManifest 引用保护和可重建的版本使用投影。
- 长期未使用运行层的具体保留与重新下载策略留给部署存储设计，不改变版本元数据和历史 Evidence。
