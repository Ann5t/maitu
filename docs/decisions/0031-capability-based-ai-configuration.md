# 0031：AI 连接与按模型能力配置相互分离

- 状态：Accepted
- 日期：2026-08-24
- 置信度：高

## 背景

同一个 AI 服务可能通过 API，也可能通过账号登录接入；同一个模型又可能同时理解文字、图片、音频和视频，或生成多种媒体。把“怎样登录服务”和“哪种工作使用哪个模型”做成同一张表，会重复配置凭据，也无法清楚表达多模态模型。

用户希望默认文字模型负责当前 Session，同时让它知道系统还配置了哪些媒体能力，并在需要时主动调用对应 AI，把结果带回当前工作现场。

## 备选方案

- 每个 Agent 只绑定一个模型，不允许调用其他媒体能力。
- 按 Provider 建立互不相通的专属配置页面。
- 设置分成连接与配置，模型通过可多选的能力分类进入统一目录。

## 决定

AI 设置明确分为两个部分：

- **连接**：描述怎样访问服务，包括 API 凭据或账号登录；负责认证状态、服务地址和秘密，不决定模型承担什么工作。
- **配置**：登记连接下可用的模型，并为每个模型勾选它实际具备的能力；不重复保存连接秘密。

第一版使用七个主要能力：

1. 文字；
2. 图片理解；
3. 音频理解，包含语音转写；
4. 视频理解；
5. 图片生成与编辑；
6. 音频生成，包含语音合成；
7. 视频生成与编辑。

一个模型可以同时勾选多项能力。PDF、代码和网页等普通文档默认归入文字处理，扫描页可以再使用图片理解。工具调用、结构化输出、上下文长度、速度和价格属于模型属性，不成为并列的媒体能力；Embedding、重排序等先放入高级或系统能力，不占据主要配置界面。

系统至少需要一个可用的默认文字模型。它承担 Session 的主要对话与推理，并只接收其他已配置能力的简短目录；需要时可以在当前 Session 内调用图片、音频或视频模型，调用结果回到默认文字模型和同一工作现场。一次媒体能力调用不会因此创建 GoalBranch 或 Session，独立目标仍必须通过 BranchProposal 拆分。

模型调用必须记录所用连接、模型、能力、输入输出引用、用量、状态和来源 Session，同时保护连接秘密。首批 Provider、具体模型、同能力存在多个模型时的选择、故障转移和运行中配置版本固定方式仍需后续确定。

## 影响

- 用户只配置一次连接，模型能力可以组合而不重复凭据。
- 主工作流保持一个默认文字模型，又能自然使用多模态能力。
- 新增 Provider 只需适配连接方式和模型目录，不改变七类主要能力的产品语义。
- 模型能力调用与目标分支并行是两种不同机制，不能用前者绕过 BranchProposal。
