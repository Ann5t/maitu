# 0037：Session 工作现场按 Agent 当前动作自动跟随

- 状态：Accepted
- 日期：2026-08-24
- 置信度：高

## 背景

用户进入 Session 时真正想看到的是 Agent 当下工作的地方：文件、浏览器、终端或对话。把所有能力永久铺成导航清单会产生大量空入口；只显示聊天又无法形成“走到 Agent 工作台旁边看它工作”的体验。浏览器断线也不能让服务器后台执行产生无法补看的空白。

## 备选方案

- 每个 Session 永远显示完整功能标签列表。
- 只显示聊天和最终文字摘要。
- 根据实际动作建立现场，并在用户未固定视图时自动跟随。

## 决定

桌面项目工作台保持目标图与 Session 工作现场同时可见，中间分隔线可以调整比例；任一侧可以临时放大并恢复。选择目标图节点只替换右侧现场，不跳离项目页面。

工作现场按 Session 实际使用情况逐步出现：

- 对话：用户、主 Agent、Proposal 和请求判断；
- 文件：编辑器、预览和准确 diff；
- 终端：命令、构建、测试、运行状态与脱敏输出；
- 浏览器：搜索、页面操作、截图、运行中的 Web 软件或受控工具界面；
- 以后插件提供的特殊交互现场，仍遵守同一按需出现规则。

不存在或从未使用的现场不显示空标签。默认启用“跟随现场”：Agent 的当前前台动作变化时，右侧切到相应现场。用户手动选择某个现场后自动跟随暂停，当前视图保持稳定；用户显式点击“继续跟随”后才恢复。

对话输入和语音输入在任何现场中都可到达，不要求先切回聊天；用户也始终能请求暂停。普通消息进入持久队列并在安全动作边界交付，暂停先要求当前行动形成安全检查点。

Agent 文本、终端日志、浏览器动作、文件变化和状态都通过有顺序的实时事件更新。客户端记录最后接收位置；断线重连时先从服务器补齐缺失的持久事件和当前快照，再继续实时订阅。临时逐字输出可以分段刷新，但会影响判断的消息、行动结果、文件变化和状态必须形成可重放记录，不能只存在于一次网络连接中。

手机一次只显示目标图或一个工作现场。点击节点从底部展开并可进入全屏现场，只显示该 Session 已经产生的少量标签；返回目标图后再次进入仍恢复该用户上次位置。对话、Proposal、MergeGate、暂停、上传和语音输入均可在移动端完成。

工作现场中来自模型、终端、网页和插件的内容都必须按来源标识并脱敏；外部页面内容不能以视觉或文本形式冒充 Fudian 的系统命令。

## 影响

- 用户看到的是 Agent 实际工作过程，不是功能目录。
- 自动跟随提供现场感，手动固定避免界面在阅读时自行跳走。
- 重连协议必须支持快照加有序增量，而不是只推送当前在线消息。
- 每用户需要保存分隔比例、最后节点、最后现场和是否跟随等界面状态。
