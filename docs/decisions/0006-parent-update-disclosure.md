# 0006：父枝干更新按需披露给运行中的子枝干

- 状态：Accepted
- 日期：2026-08-24
- 置信度：高

## 背景

一个兄弟目标获批并立即合入父枝干后，其他兄弟仍然基于旧父 commit 运行。系统需要让它们知道权威父状态已经变化，但自动同步会在 Agent 工作中途改变文件、引入冲突或污染上下文。

## 备选方案

- 其他枝干直到拟合并时才发现父枝干变化。
- 父枝干变化后自动 merge 或 rebase 所有运行中子枝干。
- 提供轻量通知和按需读取，由接收 Agent 在安全点决定是否同步。

## 决定

父枝干因获批子目标 merge 而前进后，系统向仍基于旧父 commit 运行的直接子枝干投递轻量更新通知。通知的权威来源是 Git merge commit、已接受的 Contribution 和 Evidence；默认只提供来源目标、摘要、改变路径和证据目录，完整 diff、文件与证据采用渐进式披露。

数据库只保存投递、已读和处理状态，不保存另一份文件差异或成果正文。接收 Agent 可以标记无关并继续，也可以在自己的安全 commit 后显式执行标准 Git merge 以同步父枝干。系统不得自动 rebase、reset 或修改接收方 worktree。

如果父更新和接收枝干修改路径重叠，接收方必须在下一个安全点先评估；真实 Git 冲突进入可见的冲突处理流程。没有路径重叠不等于没有语义影响，最终相关性仍由 Agent 结合自身目标判断。

## 影响

- 每次权威父更新都可被发现，但不会把完整内容自动塞进模型上下文。
- 同步是接收枝干内的显式、可审计行动，而不是后台静默改写。
- 本决策只覆盖已经审核并合入父枝干的结果；尚未完成枝干的临时发现另行设计。
- 当前实现尚未建立这种派生通知和父同步动作，需要后续补齐。
