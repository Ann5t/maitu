# 0019：正式测试前按最终领域模型干净重建

- 状态：Accepted
- 日期：2026-08-24
- 置信度：高

## 背景

当前代码和数据库是在产品结构仍持续讨论时形成的开发实现，其中包含后来决定删除或折叠的 Artifact、GoalContract、Contribution、AttentionItem、两阶段项目启动和多对象合并流程。如果同时保留旧数据读取、双写和转换路径，第一版就会背负一套从未正式发布的兼容模型，并让旧概念继续影响 API 和界面。

当前实例尚未进入承载真实数据的正式测试阶段。用户希望先把这些核心结构完全讨论确定，再上线测试，不要求保存或转换现在的项目、对话和数据库样本。

## 备选方案

- 原地增量迁移，长期保留所有旧表、旧 API 和旧数据读取能力。
- 新旧模型双写一段时间，再尝试转换。
- 正式测试前冻结目标领域模型，删除旧结构并从空数据干净重建。

## 决定

正式测试基线被用户明确批准之前，当前 Fudian 中的运行数据全部属于可丢弃开发样本，不为其编写数据转换、兼容读取或旧导出恢复功能。

开始正式测试前必须先完成并审查核心对象、稳定身份、对象关系、状态转换、权限、Git/Git LFS 与持久化边界。随后以目标模型一次性重建数据库 schema、API、事件、前端投影和测试，删除已经否定的领域结构及兼容代码，不保留新旧双写。

实际清理只能作用于已经核验为开发环境的明确数据库和存储路径；本决策不授权删除来源不明或可能含真实数据的实例。干净建库、完整纵向流程和备份导入测试通过后，用户再明确宣布进入正式测试。

从正式测试基线开始，所有持久数据必须保留。此后的 schema 变化使用版本化前向迁移、变更前备份、验证和回退方案，不能通过清空数据发布。这里的“结构定死”是核心产品语义进入承诺基线，不禁止以后增加兼容字段或通过正式决策演化模型。

## 影响

- 第一版实现不需要为未发布原型承担兼容复杂度，可以直接使用最终术语和关系。
- 当前开发项目、对话、审批和测试样本会在重建时消失，且不会由新导入器恢复。
- 既有 ADR 中“旧记录继续可读”“只追加迁移”的表述，对正式测试前的当前开发数据不再适用；其产品语义决定仍然有效。
- 正式测试是明确的数据保护分界点，必须由用户批准，不能由部署脚本或开发 Agent 自动推断。
