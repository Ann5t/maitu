# 0028：插件开发、来源、联网与文件访问均受控

- 状态：Accepted
- 日期：2026-08-24
- 置信度：高

## 背景

插件需要能够按实际需求逐步增加，但把开发中的任意目录直接暴露给正式 Session，会绕过不可变版本和安装自检。公共市场、任意网络、明文秘密和整台服务器文件访问也会显著扩大第一版的供应链与数据泄露风险。

同时，完全不提供开发入口会让创建 PPTMaster 等自有能力过于困难。需要在易开发和正式运行边界之间建立明确转换。

## 备选方案

- 正式 Session 可以直接加载任意本地开发目录。
- 第一版接入公共市场并允许自动安装、自动更新。
- 插件安装后默认获得完整网络、宿主文件和环境变量。
- 提供受控开发沙箱，正式安装后才可使用，并对来源、网络、秘密和文件逐项限权。

## 决定

Fudian 提供插件脚手架与校验工具，用于生成 `plugin.toml`、可选 `SKILL.md`、references/assets 目录和自检模板。开发中的未打包目录只能由管理员在专用测试沙箱运行；它不能被项目 Session 解析或调用。内容验证、自检和安装成功后才登记一个不可修改的正式版本。

第一版不实现公共插件市场、自动搜索或自动更新。可安装来源只有随系统发布的内置插件、管理员选择的本地目录/压缩包，以及管理员明确输入并接受预览的可信下载地址。所有来源都经过相同的摘要、权限和自检流程。

插件默认没有网络。`plugin.toml` 必须声明所需公共域名和用途，Broker 按调用授予最小网络范围。公共搜索、受控浏览器和依赖注册表访问属于各自明确的系统能力，不被普通插件网络声明自动继承。

秘密由管理员在设置中绑定到插件清单声明的具名槽位。Agent 只能知道槽位名称、用途和可用状态，不能读取原值；Broker 仅在获准调用期间注入，日志、Evidence、错误、项目文件和模型上下文都必须脱敏。

插件只获得当前 Session 获准的 worktree 快照、显式输入和隔离临时区。输出先写隔离层，Broker 校验路径、大小、类型、基线和权限后才写回当前 worktree。插件不能访问其他项目或枝干、宿主目录、Fudian 数据库、Git 凭据或直接移动 Git ref。

## 影响

- 自有插件可以快速搭骨架和测试，但开发便利不会进入正式 Session 权限面。
- 第一版避免承担市场审核、依赖投毒和自动升级恢复等额外系统。
- 私密凭据不需要暴露给 Agent，插件越权访问也有明确拦截点。
- Tool Broker 需要实现网络 allowlist、秘密槽位、隔离输入输出、路径校验和脱敏审计。
- 公共市场、发布者信任链和跨实例分发以后需要独立决策。
