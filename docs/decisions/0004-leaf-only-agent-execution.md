# 0004：只有叶子目标枝干运行工作 Agent

- 状态：Accepted
- 日期：2026-08-24
- 置信度：高

## 背景

Git 允许父分支和子分支同时前进，但 Fudian 不必把所有 Git 自由都开放成执行模型。若父 Agent 在子目标运行时继续修改文件，目标责任容易重叠，父上下文会迅速过期，也会增加本可通过目标拆分避免的冲突。

任何看似需要“父主线与子探索并行”的工作，都可以把尚未完成的主线和探索分别表达成兄弟子目标；子目标内部发现的并行工作也可以递归拆成更深的目标枝干。

## 备选方案

- 允许父子 Agent 同时运行，最终依赖 Git 处理冲突。
- 使用路径锁限制父子并发修改范围。
- 只允许目标树执行前沿的叶子枝干运行工作 Agent。

## 决定

有运行中后代目标的 GoalBranch 不得运行工作 Agent。子枝干开始前，父 Session 必须形成安全 commit、释放写租约并进入等待。多个兄弟子枝干可以并行运行；父目标尚未完成的主线工作若需并行，也必须形成边界明确的子目标。

子目标发现的新工作若属于自身范围，可以继续拆分子目标；若实际属于祖先范围，则向正确祖先提出新的兄弟 BranchProposal。Proposal 的整理、讨论和审批属于控制面，不要求恢复祖先工作 Agent。

父枝干在等待期间可以由受控整合流程接收审核通过的子枝干 merge，因此 Git HEAD 可以变化，但父工作 Agent仍不运行。只有必需子目标全部接受、明确失败或由用户有理由地豁免，且没有运行中的后代后，父枝干才创建下一 Session 恢复。

## 影响

- 同时运行的工作 Agent 对应目标树上的一个反链，不存在祖先与后代同时写入。
- 目标责任和暂停原因更清楚，代价是产生更多语义明确的子枝干；前端需要通过缩放和折叠控制密度。
- 兄弟枝干仍可能修改相同文件，最终继续使用标准 Git merge 和冲突处理。
- 当前数据库只限制同一 GoalBranch 一个 running Session，尚未阻止祖先与后代同时 running；后续必须以追加迁移和事务锁补齐，不能改写旧迁移。
