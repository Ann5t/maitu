# 0027：原生插件最少提供清单与隔离自检

- 状态：Accepted
- 日期：2026-08-24
- 置信度：高

## 背景

插件能力已经确定由共享环境、调用适配器和 Agent 说明组合，但如果每个插件都被要求实现 MCP 服务并制作完整容器，简单 CLI、模板和知识型 Skill 的接入成本仍然过高。另一方面，只放一段提示词又无法知道版本、权限、环境需求和安装是否成功。

需要为以后逐步加入 PPTMaster 等能力定义一个足够小、同时可验证的原生插件骨架。

## 备选方案

- 所有插件必须包含 MCP 服务和独立 OCI 镜像。
- 插件可以是没有清单和自检的任意脚本目录。
- 只强制规范化清单与自检，其余能力部件按需组合。

## 决定

一个 Fudian 原生插件目录或同布局压缩包至少包含：

- `plugin.toml`：稳定插件 ID、名称、版本、一句话能力、所需权限、环境资源、适配器类型、入口引用和自检入口；
- 可在隔离环境执行的自检：证明清单、依赖、入口和最小能力可用，具体可以位于 `tests/` 或由清单引用。

以下内容均为可选：

- `SKILL.md` 与 `references/`：Agent 使用方法和按需参考资料；
- `assets/`：模板、示例、字体或静态资源；
- MCP 工具服务：复杂、结构化或已有 MCP 能力；
- 专用 Runtime：无法由中央环境资源和内置执行器满足的系统环境。

已有 CLI 插件可以由 Skill 指导 Agent 通过内置受控执行器调用中央资源，不必包装 MCP 或容器。知识型插件可以只有 Skill 和清单。复杂工具再逐步添加结构化接口或 Runtime。

管理员安装时，Fudian 展示用途、来源、准确版本、预计空间、权限和环境需求，验证所有内容边界与摘要，并在隔离环境运行自检。只有全部通过才安装为不可修改版本。MCPB 等外部格式先由适配器转换为同一内部规范化清单和能力合同；外部包格式不能绕过权限、自检和版本固定。

插件内的 Skill 属于该能力的受限使用说明。它可以教 Agent 怎样调用工具，但不能覆盖系统提示、GoalBranch 权限、worktree 边界或外部写审批。

## 影响

- 简单插件接入成本接近编写一个清单和自检，不被容器化要求拖累。
- 复杂插件仍可提供 MCP、Runtime、模板和详细参考资料。
- 统一安装流程能够在能力进入 Session 前发现缺失入口、依赖和越权声明。
- 后续需定义 `plugin.toml` 的准确 schema、内置适配器枚举、自检结果格式和插件开发脚手架。
