# 0036：目标图使用语义缩放画布和稳定流程形状

- 状态：Accepted
- 日期：2026-08-24
- 置信度：高

## 背景

目标图既要让用户看到一个 Session 的实时现场，也要容纳长期项目中的大量目标枝干。若把枝干起点、暂停、恢复和每个内部事件都画成同级节点，图会重复表达目标并快速膨胀；若只做普通 Git 图，又无法进入 Agent 正在工作的现场。

## 备选方案

- 每个目标、暂停、恢复和审批都创建独立形状节点。
- 使用固定列表或传统 Git 提交图，不提供自由画布。
- 以枝干、Session 和 MergeGate 为稳定图形语义，并通过语义缩放聚合。

## 决定

项目目标图是可平移、缩放的无限画布，使用以下稳定语义：

- 实线本身代表正式 GoalBranch，也就是一个目标；枝干目标名称沿线显示，不另造“枝干起点”节点；
- 圆形代表 Agent Session；
- 菱形代表 MergeGate；
- 尚未接受的 BranchProposal 从来源 Session 显示为短虚线枝芽，批准后才成为正式枝干并产生首个 Session；
- 方框不是流程节点，只在缩放较远时概括一整条枝干，继续缩小时概括一片子树。

暂停、等待用户、异常和恢复不创建新的主要节点。状态附着在真正等待的 Session 圆形、MergeGate 菱形或 Proposal 虚线枝芽上，以光圈、状态标记和简短文字提示；完整追加式事件从该对象详情查看。

桌面悬停圆形时显示当前任务以及 Agent 当前经过脱敏的实时输出；不再运行时显示最后输出、检查点和停下原因。悬停菱形显示整合、验证、AI 审核或人工决定所处阶段。点击节点会在保留画布的同时打开对应工作现场；手机点击后从底部打开现场，不依赖悬停才能取得信息。

系统先根据父子关系和时间顺序自动布局：同一枝干上的 Session 从左到右追加，子枝干从来源 Session 分叉，兄弟枝干占用不同轨道。新工作只占用附近空位，不重排用户已经摆好的区域。

用户可以通过枝干目标名称移动整条枝干；其后代子树默认一起移动，连接线自动重排，但同一枝干内 Session 的先后顺序不能通过拖拽改变。系统提供“整理这片”和“恢复自动布局”。布局按用户与项目保存，只是可重建的界面投影，不改变 GoalBranch、Git 历史或其他用户的布局。

缩放遵循语义层级：近处显示节点与现场状态，中距离把节点收成枝干方框，远距离把子树收成区域方框。聚合框仍显示最重要的运行、等待和拟合并数量，放大后回到相同实际对象。

## 影响

- 图形不会重复表达枝干身份或把状态事件伪装成工作节点。
- 用户可以从全局子树逐层进入实时 Agent 输出，同时长期项目仍可浏览。
- 自动布局保证时序清楚，个人移动又允许形成适合自己的空间记忆。
- 实时输出通道必须脱敏、可断线恢复，并与持久事件/日志区分。
- 当前固定泳道投影和暂停节点候选属于待替换界面。
